# React Users browser cases

Run `npm ci && npx playwright install chromium --only-shell && npm test` from
`tests/browser/` while the local Docker preview is running. Set `KEEPLANE_BASE_URL=http://127.0.0.1:13000` to repeat against kind. Tests live under
the repository's top-level `tests/` tree, as required by ADR 017. The browser
suite uses the real local sign-in for BR-02 and BR-12. BR-12 creates one
disposable user and removes it afterwards. The layout and network-failure cases
use fixed API responses so they do not create accounts or depend on the current
database contents.

| Case | Plain-English action | Expected result |
| --- | --- | --- |
| BR-01 | Open the React sign-in screen without a connected SSO provider. | Username and password appear with "No account? Ask your admin."; SSO and self-registration do not. |
| BR-02 | Sign in with the infrastructure admin and open Create user. | Users opens, the break-glass row has no Change role, and Developer is preselected. |
| BR-03 | Open Users at 1280px and 320px, then open the narrow menu. | Projects is enabled and receives focus when the narrow menu opens. Approved screenshots remain stable; the narrow menu is 288px, the table scrolls within the page, the page itself does not overflow, the search field is at least 44px high, and no browser asset is fetched from another origin. |
| BR-04 | Let Create user wait ten seconds without an answer, choose Check, then retry. | The form reports uncertainty, retains the fields after a definite non-write, and retries with the same operation ID. |
| BR-05 | Change a Developer to Admin from Users against a fixed API response. | The dialog's legend reads "Role for developer-example" and its button "Change role", as in `Users-role.dc.html`. The UI calls the role endpoint, reports the new role, updates the row and puts focus back on the row's Change role. |
| BR-06 | Open Create user, press Escape, then Enter. | Focus returns to Create user and the keyboard reopens the dialog. |
| BR-07 | As soon as Users appear, click Next and wait for the initial search timer to settle. | Page 2 remains selected; the timer cannot return the table to page 1. |
| BR-08 | Sign in while the API returns a one-minute attempt limit. | The form explains the wait, retains the username, and allows another attempt. |
| BR-09 | Sign in with invalid credentials. | The same generic message hides which usernames exist. |
| BR-10 | Sign in while account storage is unavailable. | The form explains the storage problem and allows retry; it does not blame the password. |
| BR-11 | Open the web UI as a developer at desktop and 320px widths. | It shows the CLI prerequisite, a sign-in command using this server and an explicit private profile, and the device option. The page stays within the viewport and loads no admin navigation or admin APIs. |
| BR-12 | Against the running server, sign in as the infrastructure admin, create an Admin, search for it, change it to Developer, sign out and sign in as that user. | Users shows the new user with each role in turn; the user then sees the developer page with no admin navigation, and the Users API refuses them. The test removes its user afterwards. |
| BR-13 | Open the React sign-in screen at 1280px and 320px. | The card title "Sign in" is IBM Plex Sans 28px on 36px at 600, the design system's `page-title`, as on the designed sign-in card (`Main.dc.html`, `Main-no-sso.dc.html`, `Main-failed.dc.html`) and the CLI sign-in pages. The page fits the width. |
| BR-14 | At 320px, create a user with a 64-character username, the longest allowed, while Keeplane refuses it with a fixed answer, then change the username. | The failure says "[Username] wasn't created" with the whole username Keeplane refused, as in `Users-create-failed.dc.html`, followed by the reason and "Nothing was saved. Check the details and try again." The title wraps inside the dialog and the page fits the width. It keeps naming the refused username after the field changes. |
| BR-15 | Open the React sign-in screen at 1280px and 320px, without and then with a connected SSO provider, and sign in with a wrong password each time. | As in `Main-no-sso.dc.html`, `Main.dc.html` and `Main-failed.dc.html`: the 40px Keeplane mark and "Keeplane" at 20px 600 sit above "Sign in". Under the Sign in button, in 14px on 20px `ink-muted`, the card says "No account? Ask your admin." without SSO, or "No account? Signing in with single sign-on creates one. For a username and password, ask your admin." with it, followed by "Sign in with single sign-on" as an outline button at least 44px tall. The wrong password shows "The username or password is wrong." as the design system's failure message: on `ground` with a `control-border` edge, 8px corners, 14px 16px padding, a 20px circle-alert icon, and the line at 15px on 22px, weight 600. The page fits the width. |
| BR-16 | At 1280px and 320px, create a user while Keeplane refuses it (409), then while it answers with a server error (503). | "example-user wasn't created" (`Users-create-failed.dc.html`) and "It isn't clear whether example-user was created" (`Users-create-no-answer.dc.html`) each show as the same failure message, with a circle-alert icon, not a triangle, and the title at 15px on 22px, weight 600. The page fits the width. |
| BR-17 | At 1280px and 320px, change a Developer to Admin while Keeplane refuses it (404), then while it answers with a server error (503), then while the connection drops with no answer. | Inside the dialog, above its buttons, "developer-example's role wasn't changed" with "Account not found. Nothing was saved. Check the details and try again.", then "It isn't clear whether developer-example's role was changed" with "Keeplane couldn't confirm the result. Check to find out.", then the same title with "Keeplane didn't answer in time. Check to find out." Each is the design system's failure message, as in BR-15: a 20px circle-alert icon, not a triangle, and the title at 15px on 22px, weight 600. The page fits the width. |
| BR-18 | At 1280px and 320px, change a Developer to Admin while Keeplane makes the change but holds its answer past 10 seconds, then choose Check. | While saving, the dialog says "Saving" to screen readers, its roles and buttons are off and Escape doesn't close it. At 10 seconds it shows "It isn't clear whether developer-example's role was changed" and "Keeplane didn't answer in time. Check to find out." as the design system's failure message above Cancel and Check, as in `Users-create-no-answer.dc.html`. Check reads the role back, closes the dialog and Users shows Admin. The change was sent once and the page fits the width. |

The real Docker and kind account and Audit suites separately test backend permissions,
database effects and idempotent writes. Browser mocks here isolate UI behavior.
