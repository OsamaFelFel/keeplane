The first failover trial exposed a real failure: one of ten new calls received
HTTP 503 immediately after pod deletion. The [initial run](2026-10-08-kind-failover.json)
records it. A [diagnostic repeat](2026-10-08-kind-failover-diagnostic.json)
identified a refused TCP connection while Kubernetes removed the endpoint.
Keeplane now retries only connection-refused errors on
new question calls, where the request never reached a gateway. Three
consecutive failover runs passed, each with ten new calls; the final run is
recorded above. This does not guarantee availability under every failure.

The existing-gateway trial uses the same upstream gateway in another
namespace, rather than a customer-owned instance. The disposable database
loses data when its pod is replaced. No external egress restriction, real
provider integration, streaming interruption, node failure, or production
secret management was tested. The customer-installable release remains open.
