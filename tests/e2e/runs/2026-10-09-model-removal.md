# Local model removal and regression — 9 October 2026

The protected Docker preview now distinguishes models Keeplane registered
from models added directly to the gateway. A new catalog column records
ownership. The admin removal dialog follows the
approved Model-remove canvas: a Keeplane-owned model is removed from the
gateway, while removing setup for an outside model preserves its gateway
definition.

The [plain-English cases](../model-removal-cases.md),
[live verifier](../test_model_removal.py), and
[JSON result](2026-10-09-model-removal.json) are versioned. **7/7 live cases
passed** against the actual agentgateway and protected account preview.
They include admin-action refusal, gateway deletion, preservation of an
outside model, and refusal to delete a definition changed by another gateway
writer. Reapproving such a changed definition records it as outside Keeplane.
The catalog unit check verifies that a changed gateway definition cannot inherit approval.

The actual admin UI was inspected through the isolated loopback fixture after
the live run. **REMOVE-UI-01 through 03 passed:** the owned-model dialog named
the model and explained gateway deletion; canceling and reopening it showed
the same complete message; the outside-model dialog said the gateway model
would stay. The first visual pass found a repeat-open script error, which was
fixed before the recorded pass. The fixture uses the shipped UI files with
fixed model responses, so this check covers dialog interaction and layout,
while the live verifier covers gateway effects.

The [full local regression manifest](2026-10-09-model-removal-regression.json)
records **24/24 suites and 120 case records passing**, across Docker, kind,
Qwen, gateway failover, accounts, data classes, audit, model registration,
cloud listing, replacement, edit, runtime limits, and removal. The first
host invocation of the management-read unit suite lacked
`PYTHONPATH=components/control-plane` and failed before any case ran. The
corrected invocation passed 3/3 cases and both attempts are recorded in the
manifest. Dated reports generated by existing suites were restored to their
previous committed versions; this new manifest keeps the present run's case
IDs and verdicts.
After the focused rerun and visual check, Docker and kind `/health` both
returned HTTP 200. Port 3001 gave the expected sign-in redirect, and all six
pods in the isolated `kind-keeplane` namespace were Running and Ready.

This is a local preview slice of Spec 004 ST23. Complexity-level and persona
rules are not implemented yet, so it does not exercise the spec's “model in
use” removal guard. The gateway management API used here has no tested
conditional DELETE; the immediate fingerprint check rejects a changed
definition observed before removal, but concurrent external replacement
between that read and DELETE remains a release design concern. No release
gateway is selected by this trial.
