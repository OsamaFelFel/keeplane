# 10 October 2026 — full Keeplane through TLS Ingress and Calico

The [plain-English cases](../full-product-edge-cases.md), [repeatable verifier](../test_full_product_edge.py), and [confirmed JSON result](2026-10-10-full-product-edge-confirmed.json) cover the actual Keeplane Helm chart in a separate `keeplane-netpol` kind cluster. It had Calico 3.33.0 and a disposable ingress-nginx v1.15.1 controller. The test installed one managed agentgateway replica, the app, a model fixture, PostgreSQL test fixture, the app-only TLS Ingress, and the managed-gateway ingress NetworkPolicy. The generated certificate, first-admin password, and gateway keys were not saved in this repo. The test namespace and port-forward were removed. The main Docker and kind previews were untouched.

All five cases passed. A client verified TLS and received the sign-in redirect; the first admin signed in over HTTPS and read `/api/identity`; `/api/models` returned 200 through the app and gateway. A sibling model pod in the same namespace timed out calling the internal gateway Service while the app remained able to list models. The installed NetworkPolicy selected this release's gateway pods. The [first passing run](2026-10-10-full-product-edge.json) recorded the sibling's broad `URLError`; the confirmed run distinguished the underlying `TimeoutError`.

This proves the app and managed gateway work together behind this local Ingress and one enforcing CNI. It does not prove a production package: the PostgreSQL and model workloads are disposable fixtures, SQLite still holds local account state, there was one gateway replica, and this run did not exercise project-bound runtime policy, a customer-run gateway, pod-label administration, full default-deny/egress rules, certificate renewal, or an install without registry access.
