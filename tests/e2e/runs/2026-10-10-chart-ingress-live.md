# 10 October 2026 — live TLS Ingress fixture

The [plain-English cases](../ingress-cases.md), [verifier](../test_chart_ingress.py), [pinned workloads](../ingress/workloads.yaml) and [passing result](2026-10-10-chart-ingress-live-retry.json) test the actual Keeplane app Ingress template in the separate `keeplane-netpol` kind cluster. Calico 3.33.0 and the upstream ingress-nginx v1.15.1 kind manifest ran there; this controller is a disposable fixture, not a Keeplane release dependency. The manifest had SHA-256 `2a3ae008c8786431115502644e77ab398fdebfb721a5d1195ed3089cde3299df`. A generated certificate and key stayed in a private temporary directory and Kubernetes test Secret. The verifier removed its namespace and port-forward.

All four cases passed. A curl client trusted the generated certificate and reached `app:/` over HTTPS. A request for `/api/config/resources/llm.model` went to the app fixture, not the separate gateway fixture. Plain HTTP returned 308 to the HTTPS host. An unrelated HTTPS host returned 404. The [first attempt](2026-10-10-chart-ingress-live.json) saw the controller's default certificate before the new host route had loaded; the verifier now waits for a trusted response before recording a route verdict.

This proves the rendered route with one controller and a fixture app. It does not prove the full Keeplane UI/API through the Ingress, another customer's controller, production certificate renewal, namespace access restrictions or the future project-bound model runtime path. The main Docker and kind product previews were not changed.
