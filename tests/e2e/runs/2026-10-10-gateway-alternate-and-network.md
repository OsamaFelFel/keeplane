# 10 October 2026 — alternate gateway paths and ingress boundary

The [bypass cases](../gateway-bypass-cases.md), [probe](../test_gateway_bypass_probe.py), and [Docker/kind result](2026-10-10-gateway-alternate-paths.json) checked the exact pinned agentgateway image. Credential-free sibling workloads got HTTP 401 from model listing, management and key APIs, ordinary chat, forged-header chat, streaming chat, tool chat, OpenAI Responses and Anthropic Messages. The local fixture recorded zero added upstream calls. The public Keeplane routes also returned 401 without a session. The [isolated two-key repeat](2026-10-10-gateway-strict-alternate.json) confirmed the same alternate-path refusals while the runtime key retained model-list/chat access and the separate admin key retained management access.

The [chart packaging cases](../chart-package-cases.md) and [render result](2026-10-10-chart-package-network-policy.json) cover an **opt-in** managed-gateway ingress NetworkPolicy. The rendered selectors match the managed gateway and app pod labels. Existing-gateway mode rejects this setting because Keeplane does not own the customer's gateway namespace. The setting remains off in the running local kind preview, whose default CNI has not been validated for policy enforcement.

The [network cases](../network-policy-cases.md), [verifier](../test_network_policy.py), and [five passing observations](2026-10-10-network-policy-calico-final.json) used a separate `keeplane-netpol` kind cluster with Calico 3.33.0. Before policy, both app and sibling reached a fixture gateway. With policy, the app still got HTTP 200 and the sibling connection failed. Giving the sibling the trusted app label restored access; removing that label blocked it again. Deleting the policy restored sibling access. This is a concrete reason to restrict pod creation and relabeling in a production namespace. The test used a tiny HTTP fixture with the chart's real labels, not a full Keeplane installation. Earlier [digest-import](2026-10-10-network-policy-calico.json), [unqualified-alias](2026-10-10-network-policy-calico-corrected.json), and [qualified-alias](2026-10-10-network-policy-calico-qualified.json) attempts failed during fixture startup; the [first digest run](2026-10-10-network-policy-calico-digest.json) passed the block but stopped on a test-script label update. All failed runs are preserved as setup evidence.

These results close the **tested anonymous alternate paths** and establish the chart policy's ingress selector behavior on one enforcing CNI. They do not establish project-bound identity, data-class decisions after routing and fallback, protection from a pod actor allowed to spoof labels, provider-direct egress control, management isolation for a customer-run gateway, production CNI compatibility, or a customer-installable gateway artifact. The release gateway remains unselected.

The [full Docker/kind regression](2026-10-10-gateway-network-regression.json) passed **34/34 suites and 179 case records**, including the new chart case. The running local kind release was not changed to use the policy. Docker and kind previews still returned their expected sign-in redirects after the run.
