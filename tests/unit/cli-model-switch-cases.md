# See which model answered, and switch with `keeplane use`

Spec 004 ST17 "See the model", "Switch the model" and "My switch beats Keeplane's
picks" (D105, D150, ADR 030); the CLI side of ST12, ST14 and ST16. Wording
decided by the associate product owner for task 009-07. Journey: DEV-02,
DEV-03. Synthetic server and runtime doubles in a sample clone; run
`python -m pytest tests/unit/test_cli_model_switch.py`. The real routes are in
the [integration cases](../integration/cli-model-switch-cases.md).

| Case | Expected result |
| --- | --- |
| SW-01 Switch | `keeplane use general` with `general` allowed prints "This repo's next tasks use general. Run `keeplane use --auto` to let Keeplane choose again." It saves `general` under the repo's project ID in the private (0600) settings file, and asks only for the account, the repo's first-use record (as `code` does) and the allowed list. Another project has no switch. |
| SW-02 Not allowed | `keeplane use outside` for a model the project doesn't allow exits 1 with "outside isn't allowed for this project. Nothing was saved. Choose one that `keeplane models` lists." No settings file is written. |
| SW-03 Code uses the switch | `keeplane code "task"` sends the switch as the `task-model` route's `model_id`, runs that model, says "Using general for this task, as you chose with `keeplane use`. Run `keeplane use --auto` to let Keeplane choose." and, after the turn, "Answered by general." |
| SW-04 Back to Keeplane's pick | `keeplane use --auto` clears the switch without a sign-in or any request, and says "This repo's next tasks use the model Keeplane chooses." `code` then asks the route with no model and says "Using coder for this task, chosen by Keeplane. Run `keeplane use <model>` to choose another." |
| SW-05 The list marks the next task's model | `keeplane models` marks the model the next task uses (`"current": true`) and says who chose it (`"chosen_by"`: `keeplane` or `you`). With a switch it asks the route about the switch. When the developer's own key for it is missing or refused, the server's model is marked, chosen by `keeplane`, and stderr says "Your own key for general is missing, so your next task uses coder. Run `keeplane keys list` to see your keys." A switch no task can use marks nothing and says why, for example "general is approved for this project but can't be used right now. Try again in a few minutes." A switch the project no longer allows, whether the CLI's list or the server's 403 catches it, marks nothing and prints the switch-not-allowed message without ", so nothing was sent". If the pick can't be asked (404, 503), the list still shows, unmarked. A settings file that isn't valid loses only the mark, with "… Your `keeplane use` choice isn't shown in this list until the file is fixed."; `code` still stops on it. |
| SW-06 Switch no longer allowed | `code` with such a switch sends nothing and says "You switched this repo to retired, but it isn't allowed for this project any more, so nothing was sent. Run `keeplane use <model>` with a model `keeplane models` lists, or `keeplane use --auto` to let Keeplane choose." The server's 403 for the model gives the same message. Any other 403 prints the server's own short reason as its own sentence with one full stop, then "Nothing was sent.", such as "This project is unavailable. Nothing was sent."; a reason that isn't short plain text falls back to "The requested action is unavailable.": over 200 characters, an escape or C1 control, a non-ASCII character, a newline, a body that isn't JSON, or one over 4 KB (at most 4 KB plus one byte is read). A printable reason of exactly 200 characters is shown, followed by " Nothing was sent." |
| SW-07 Own key unusable | When the server moves the switched task because the developer's own key is missing or refused, `code` says "Your own key for general is missing, so this task uses coder. Run `keeplane keys list` to see your keys." ("is refused" when the provider refused it), runs the server's model, and ends "Answered by coder." The switch is kept. With no other model, nothing is sent. |
| SW-08 Switch can't be used now | A switched model the gateway can't take right now stops with the existing "… can't be used right now, so nothing was sent" message. |
| SW-09 Older server | With no `task-model` route (404), the switch goes through the model-choice route. |
| SW-10 One turn | `--model coder` is for that turn only: the route isn't asked and the switch stays. |
| SW-11 Answers that don't match | A route answer that drops or replaces the switch, claims a developer switch that wasn't sent, moves a model to itself, names a persona not asked for, or is otherwise inconsistent is refused as an invalid model choice. |
| SW-12 Messages | "Answered by [Model]." only after a finished turn, naming every allowed model the runtime's events name, in order ("Answered by coder and general."), or the model sent when none is named. The ST16 messages say "Wait and try again, or run `keeplane use <model>` …" and "Make the task smaller, or run `keeplane use <model>` …"; their first sentences and the decided #52 and #57 sentences are unchanged. |
| SW-13 Use needs one model or --auto | `use` with neither or both exits 2. Signed out: "You're signed out of Keeplane, so nothing was saved. Run `keeplane login` to sign in." Expired: "Your Keeplane sign-in has expired. Nothing was saved. Run `keeplane login` to sign in again." |
| SW-14 Empty list | With no models allowed, as on a new installation, `keeplane models` prints only `{"project_id": …, "models": [], "chosen_by": null}` and nothing on stderr, as the preview case PSI-LIVE-03 expects. |
